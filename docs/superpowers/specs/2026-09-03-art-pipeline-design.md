## 1. 스프라이트 규격

### 픽셀 단위와 배율
- 무대는 가로 **360 픽셀 단위**의 가상 해상도로 설계하고 기기 가로폭에 맞춰 통째로 확대한다. 375pt 기기에서 약 1.04배.
- 확대는 최근접 보간(블러 없음). 액터 위치는 정수 픽셀 단위로 반올림한다.

### 크기

| 대상 | 픽셀 크기 | 비고 |
|---|---|---|
| 주인공·동료 | **56×56** | PixelLab 표준 모드가 48 요청에 키 50px 캐릭터를 68 캔버스로 주므로 56 창으로 묶는다(스파이크 결정 2026-09-04) |
| 일반 몬스터 | 48×48 | v3 모드는 요청 크기 그대로 |
| 펫 새끼 용 | 32×32 | 주인공 옆 |
| 펫 성체 용 | 48×48 | 진화 후 |
| 보스 | 96×96 | 지역당 1종 |
| 아이템 아이콘 | 32×32 | 인벤토리·도감·드롭 연출 공용 |

### 방향
- 묶인 시트는 **항상 오른쪽을 본다**. 앱은 적을 좌우 반전해 왼쪽을 보게 한다.
- 생성은 동쪽·서쪽 중 **무기가 앞에 보이는 쪽** 하나만 쓴다. 주인공은 왼팔 방패가 앞을 가리므로 서쪽 뷰를 뽑아 `--flip`으로 반전해 묶고, 몬스터는 동쪽 뷰를 그대로 묶는다(스파이크 결정 2026-09-04).

### 애니메이션 세트 (모든 캐릭터 공통)

스파이크는 무료 40회 예산 때문에 `idle`·`attack`·`hit` 3종만 뽑았다. 출시 물량은 5종 전부.
PixelLab 사용 규칙: 사람형은 표준 모드(1회) + 템플릿 애니메이션(방향당 1회, `breathing-idle`·`taking-punch`), 검 베기는 v3 커스텀(1회). 슬라임·용·골렘 같은 비인간형은 **v3 모드 생성(48px 2회, 96px 3회)** + v3 커스텀 애니메이션(방향당 1회). 방향은 반드시 하나만 지정한다(기본은 전 방향이라 4~8배 비용).

| 이름 | 프레임 | 용도 |
|---|---|---|
| idle | 4 | 대기 |
| walk | 6 | 스테이지 입장, 몬스터 접근 |
| attack | 6 | 기본 공격과 스킬 공용. 직업별 동작 다름(베기·활·찌르기·지팡이) |
| hit | 2 | 피격. 백플래시와 함께 |
| death | 6 | 사망·포획 |

스킬은 attack 모션 위에 VFX를 얹는다. 별도 모션 없음.

### 첫 출시 물량

| 그룹 | 시트 수 | 산출 |
|---|---|---|
| 주인공 | 8 | 4직업 × (기본 + 1차 전직) |
| 펫 | 10 | 용 5속성 × (새끼 + 성체) |
| 몬스터 기본 형태 | 20 | 지역 5 × 형태 4. 나머지 80종은 앱 팔레트 스왑 |
| 보스 | 5 | 지역당 1 |
| 아이템 아이콘 | 약 60 | 부위 6 × 등급 5 × 2 변형 (서브프로젝트 4에서 확정) |

팔레트 스왑을 위해 몬스터는 눈·외곽선을 어두운 색으로 고정하고 몸통 색만 바뀌게 프롬프트에 넣는다(기존 `ART_GUIDE.md` 원칙 유지).

### 파일 규격
- 시트: 프레임을 가로로 나열한 PNG 1장 + JSON 1개(프레임 크기, 애니메이션별 프레임 범위, fps).
- 경로: `assets/sprites/<그룹>/<id>.png` 와 `.json`. 그룹은 `hero` `pet` `monster` `boss`. 아이콘은 `assets/icons/items/<id>.png`. 배경은 `assets/backgrounds/<지역 id>/far.png` `ground.png`. 이펙트는 `assets/vfx/<id>.png` + `.json`.
- id는 마스터 데이터의 id를 그대로 쓴다.

JSON 예:

```json
{
  "frame": [48, 48],
  "fps": 8,
  "animations": {
    "idle": [0, 3],
    "walk": [4, 9],
    "attack": [10, 15],
    "hit": [16, 17],
    "death": [18, 23]
  }
}
```

## 2. 도구 연결과 생성 순서

### 역할 분담

| 역할 | 도구 | 연결 |
|---|---|---|
| 캐릭터·애니메이션 | PixelLab MCP | HTTP MCP 서버(`https://api.pixellab.ai/mcp`). pixellab.ai 가입 후 API 토큰. 도구 `create_character`(4/8방향), `animate_character`(idle·walk·attack 등) |
| 배경 | PixelLab `create_image_pixflux` (360×272, 1회) | 캐릭터와 같은 도구라 화풍이 맞고 처음부터 픽셀아트로 나온다. `bg_pixelize.py`로 270 크롭 + far/ground 분리. 외부 모델 그림은 `image_to_pixelart`로 변환해 같은 경로로(스파이크 결정 2026-09-04) |
| 이펙트 | 무료 픽셀 VFX 팩 + Flame 파티클 | itch.io CC0 계열(예: pimen). 파일별 상업 이용 가능 여부를 `ART_GUIDE.md`에 기록 |

PixelLab은 크레딧제. 스파이크에서 시트 6개의 소모량을 재고 43시트 전체 예산을 산출한다. 생성은 비동기(2~5분)라 여러 개를 한 번에 걸어 둔다.

### 연결 절차
1. pixellab.ai 가입 → API 토큰 발급 (사용자)
2. 프로젝트 `.mcp.json`에 서버 등록. 토큰은 환경 변수 참조, 파일에 넣지 않음
3. 세션 재시작 → `create_character` 호출 확인

### 생성 순서 = 스파이크

| 단계 | 산출물 | 목적 |
|---|---|---|
| 1 | 전사 기본 48px 동쪽 정지 1장을 여러 번 | 화풍 앵커 결정. 이후 모든 생성의 스타일 기준 |
| 2 | 전사 기본, 전사 1차, 아기 용(화), 숲 몬스터 2종(슬라임·개구리), 숲 보스 96px — 각 5애니메이션 | 시트 6개. 전직이 보이는가, 보스가 위압적인가, 같은 붓인가 |
| 3 | 숲 배경 1장 → 2레이어 | 배경과 캐릭터 화풍 충돌 확인 |
| 4 | 전사 원형 강타 이펙트 1개 + 피격 파티클 | 타격감 재료 |
| 5 | Flame 무대에 아군 2(전사+용) 대 몬스터 3+보스, 자동 공격 목업 | 엔진 수정 없이 시각만. 실기기 375pt |

### 합격 기준 (전부 통과해야 확정)
1. 픽셀 확대가 깨끗하다 (블러·불균일 픽셀 없음)
2. 시트 6개가 같은 화풍으로 보인다
3. 타격감: 히트스톱·백플래시·화면 흔들림·파티클·데미지 숫자가 실기기에서 60fps
4. 팔레트 스왑이 픽셀 스프라이트에서 먹힌다 (눈·외곽선 유지)
5. 크레딧 소모가 43시트 예산 안

### 실패 시 분기
- 2 실패 → 캐릭터 도구를 Gamelabs 또는 에셋 팩으로 교체. 나머지 파이프라인 유지
- 3 실패 → 엔진 재논의
- 그 외 → 규격 조정

## 3. Flame 무대 구조

도메인(`domain/battle_engine.dart`)은 Flame을 모른다. 이 분리를 유지하고 무대 안쪽만 바꾼다.

### 카메라
- 가상 해상도 360×270 고정 뷰포트. 최근접 보간. 액터 위치 정수 반올림.
- `FlameGame`이 기본으로 갖는 `world`·`camera`를 쓴다(생성자 `camera:` 인자로 고정 해상도 카메라 전달). **`camera.viewfinder.anchor = Anchor.topLeft`** 로 무대 원점을 좌상단에 둔다(기본은 중앙).

### 레이어 (아래→위)

| 레이어 | 내용 | 비고 |
|---|---|---|
| 배경 원경 | `far.png` | 스테이지 전환 시 느린 가로 이동 |
| 지면 | `ground.png` | 고정. 3/4 원근은 그림에 포함 |
| 액터 | 주인공·펫·동료·몬스터·보스 | y 정렬: 발 위치 y가 클수록 앞 |
| 이펙트 | VFX 시트 애니메이션, 피격 파티클 | 액터 위 |
| 표시 | 몬스터 발밑 소형 HP 바, 데미지 숫자 | 보스 HP 바는 Flutter HUD |
| 흔들림 루트 | 위 전부를 감싸는 기존 `_StageRoot` | 화면 흔들림·히트스톱 적용 지점 |

### 컴포넌트
- **시트 로더**: PNG+JSON → 애니메이션 이름별 `SpriteAnimation` 맵. id별 캐시. 누락 애니메이션은 로드 실패.
- **액터**: 단일 클래스. 상태 기계 idle → walk → attack → hit → death(death 후 전이 금지), 좌우 반전, 팔레트 스왑(ColorFilter), 발밑 타원 그림자, 백플래시. 주인공·동료·펫·몬스터·보스는 크기와 데이터만 다르다. 서브클래스 없음.
- **백플래시는 스프라이트 페인트의 `ColorFilter.mode(white, srcATop)`** 로 한다. `renderTree`에서 `saveLayer`를 잡는 방식은 부모 좌표계에서 잘려 스프라이트가 사라진다(스파이크에서 확인). 플래시 동안은 팔레트 필터 대신 흰색 필터가 들어가고 끝나면 복원한다.
- **진형**: 픽셀 단위 슬롯 테이블. 아군은 왼쪽(주인공 중앙, 펫 옆, 동료 3은 뒤쪽 호). 몬스터는 오른쪽 3~5 슬롯을 앞뒤로 어긋나게, 보스는 오른쪽 중앙 단독.
- **VFX**: 위치 지정 일회성 애니메이션. 속성 팔레트 스왑은 액터와 같은 ColorFilter.
- **히트스톱**: 스킬·치명타·처치 시 액터 레이어 시간만 50ms 정지.
- **데미지 숫자**: 기존 `FloatingDamage` 유지(최대 6개·흩뿌림).

### 도메인 → 무대 이벤트 (단방향)
공격 시작 / 피격(대상·데미지·치명·속성) / 스킬 발동(스킬 id·타깃 형태) / 사망 / 포획 / 스테이지 전환.
무대는 이벤트를 받아 재생만 한다. 무대가 엔진 상태를 읽지 않는다. 다중 타깃 이벤트는 서브프로젝트 3에서 오고, 스파이크는 목업 이벤트로 돌린다.

### 테스트
- 단위: 시트 JSON 파싱, 액터 상태 전이, 슬롯 좌표 테이블, 이벤트별 액터 반응.
- 화면: 실기기. 스파이크 캡처를 `ART_GUIDE.md` 기준 이미지로 남긴다.

## 4. 화면 레이아웃

무대는 항상 보이고 아래는 탭으로 바꾼다.

| 영역 | 높이 (375pt) | 내용 |
|---|---|---|
| 헤더 | 48 | 스테이지 번호·지역 칩·보스 타이머·골드 |
| 무대 | 가상 360×270 → 375×281 | 4:3 고정, 폭 맞춤 |
| 스킬 바 | 60 | 직업 스킬 3 + 펫 스킬 1. 쿨타임 원형 게이지. 자동 발동 시에도 게이지 표시 |
| 탭 내용 | 나머지 | 스크롤 |
| 탭 바 | 48 | 강화 · 편성 · 장비 · 도감 |

탭 내용:
- **강화**(기본): 골드·DPS 요약 + 능력치 5종.
- **편성**: 동료 3 + 펫 1. 알 상태면 부화 타이머와 광고 단축 버튼.
- **장비**: 보이는 슬롯 3 + 스탯 슬롯, 인벤토리, 일괄 분해. 서브프로젝트 4 전까지 자리만.
- **도감**: 기존 도감을 탭 안으로. 획득처 표기.

작은 기기(375×667): 무대 비율 유지, 탭 내용 약 165pt로 스크롤.

바뀌는 파일: `game_screen.dart`(탭 골격), `battle_area.dart`(무대 + 스킬 바만), `party_row.dart`·업그레이드 목록(탭 내용으로 이동), `codex_screen.dart`(탭 내용으로).

스파이크는 무대 영역만 바꾸고 아래는 기존 화면 유지. 탭 구조는 2단계에서 붙인다.

## 5. 검증 순서와 일정

### 0단계. 준비 (사용자)
- pixellab.ai 가입·API 토큰
- 배경 이미지 모델 결정
- 실기기 1대(375pt급)

### 1단계. 스파이크 — 약 3~4일
2장 순서대로 시트 6·배경 1·이펙트 1을 뽑아 무대 목업에 올린다. 산출물:
- 실기기 캡처 5장(화풍 앵커, 무리 배치, 피격 순간, 보스, 팔레트 스왑 변종)
- 합격 기준 5개 판정표 + 크레딧 소모 기록
- `ART_GUIDE.md` 결정 기록 갱신(합격이면 픽셀 규격으로 전면 교체)

### 2단계. 파이프라인 구현 — 약 1주

| 순서 | 작업 | 검증 |
|---|---|---|
| 1 | 시트 로더 | 단위: JSON 파싱, 누락 시 실패 |
| 2 | 액터 | 단위: 상태 전이, death 후 전이 금지 |
| 3 | 진형 슬롯 + y 정렬 | 슬롯 테이블 테스트, 실기기 겹침 |
| 4 | VFX·히트스톱·데미지 숫자 | 실기기 60fps(성능 오버레이) |
| 5 | 이벤트 브리지(목업 포함) | 이벤트별 액터 반응 테스트 |
| 6 | 배경 2레이어·패럴랙스 | 실기기 |
| 7 | 탭 골격(장비 빈칸) | 위젯: 탭 전환, 작은 기기 스크롤 |
| 8 | 벡터 페인터 제거, pubspec 에셋 등록 | 빌드·기존 테스트 통과 |

### 3단계. 물량 생성 — 이후 주차 병렬
주인공 8 → 숲 지역 전체(몬스터 4·보스 1·배경 1) → 나머지 지역. 지역 하나 완성마다 앱에 넣어 확인. 몬스터 100종의 지역·기본 형태 매핑은 마스터 데이터 필드로 추가하고, 서브프로젝트 2·4 결정을 받아 물량 확정.

## 6. 이 스펙이 다루지 않는 것
무리 전투 엔진의 다중 타깃 로직(3), 스킬 데이터 구조(2), 장비 화면 내용(4), 알·펫 로직(5), BM 상품(6), 마일스톤(7).

## 6. 아트 디렉션 규칙 — 에셋 구매 전 체크리스트 (2026-09-04 추가)

1~5절은 **파일이 어떻게 생겼는가**를 정한다. 이 절은 **그림이 어떻게 보이는가**를 정한다.
지난 목업이 싸구려로 보인 진짜 원인은 해상도가 아니라 이것이 없었다는 점이다.
각 스프라이트가 따로 만들어져 팔레트·외곽선·광원·눈높이가 제각각이면 한 게임으로 읽히지 않는다.

에셋을 사거나 발주하기 전에 아래를 통과하는지 본다. **하나라도 어긋나면 사지 않는다.**
이미 산 것을 고치는 비용이 안 사는 비용보다 크다.

### 6.1 통과 기준 일곱 줄

| 항목 | 기준 | 어기면 생기는 일 |
|---|---|---|
| 외곽선 | 모든 액터에 1픽셀 어두운 외곽선. 굵기가 섞이지 않는다 | 어떤 것은 스티커, 어떤 것은 수채화로 보인다 |
| 광원 | 빛은 항상 **왼쪽 위**. 그림자는 오른쪽 아래 | 캐릭터마다 다른 시간대에 서 있는 것처럼 보인다 |
| 접지 | 발밑에 타원 그림자 하나. 바닥선이 스프라이트 하단에서 2픽셀 위 | 캐릭터가 바닥에 떠 보인다 |
| 눈높이 | 사람형은 캔버스 위에서 30% 지점에 눈 | 나란히 세우면 키가 들쭉날쭉해 보인다 |
| 팔레트 | 지역별 기본 8색 + 공통 어두운 색 4개. 총 12색을 넘지 않는다 | 색이 많을수록 픽셀아트가 아니라 축소한 그림으로 보인다 |
| 채도 | 배경은 캐릭터보다 채도를 낮춘다 | 캐릭터가 배경에 묻힌다 |
| 실루엣 | 검게 칠했을 때 무엇인지 구분되어야 한다 | 전투 중에 무엇을 때리는지 모른다 |

### 6.2 구매 시 확인 순서

1. 팩 안의 스프라이트 3개를 골라 **같은 화면에 나란히 놓아 본다**. 어색하면 팩 안에서도 일관성이 없는 것이다.
2. 우리 배경 위에 올려 본다. 채도와 외곽선이 배경과 싸우지 않아야 한다.
3. 프레임 수와 애니메이션 이름이 1절의 5종과 맞는지 본다. 안 맞으면 `tools/sheet_pack.py`로 다시 묶을 수 있는 형태인지 본다.
4. **라이선스에 상업적 사용이 명시되어 있는지 본다.** 무료 팩 중 다수가 비상업 전용이다.
   (Kenmi의 Cute Fantasy RPG는 비상업 전용이라 이 프로젝트에 못 쓴다. Zerie의 팩은 상업 사용이 허용된다.)
5. 원본은 `pack/`에 두고 커밋하지 않는다. 재배포 금지 조항이 있는 팩이 대부분이다.

### 6.3 여러 출처를 섞을 때

한 사람이 그린 팩 하나로 다 채우는 것이 가장 좋다. 그럴 수 없으면 **주인공·펫·보스를 한 출처로 묶고**
일반 몬스터만 다른 출처를 쓴다. 눈이 오래 머무는 것부터 통일한다.

섞은 뒤에는 반드시 후처리 한 번을 거친다.

- 팔레트 축소로 색 수를 12색 이하로 맞춘다(`tools/`에 스크립트를 추가한다).
- 외곽선이 없는 스프라이트에는 외곽선을 넣는다.
- 눈높이가 어긋나면 캔버스 안에서 위아래로 밀어 맞춘다.

후처리를 할 수 없는 형식(벡터·3D 렌더 스프라이트)은 애초에 사지 않는다.

### 6.4 이 절이 끝나야 다음으로 간다

에셋 구매 → 교체 → 움직임 손맛 조정 순이다. 손맛(감속·타격 정지·잔상)은 최종 그림이 들어온 뒤에 잡는다.
임시 그림으로 잡아 두면 두 번 하게 된다.
