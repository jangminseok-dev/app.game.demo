# 화면 지도 설계 (2026-09-05)

> 이 문서는 **"무슨 화면이 있고 어디서 열리고 무엇이 그 안에 있는가"**를 정한다.
> 화풍(한 칸 안에 무엇을 넣는가)은 `2026-09-04-creature-art-direction-design.md`와 `ART_GUIDE.md`가,
> 파이프라인은 `2026-09-03-art-pipeline-design.md`가 정한다.
> 세계관은 `GAME_DESIGN.md` 18장을 따른다.

## 0. 왜 쓰는가

레퍼런스(「99강화 나무몽둥이: 키우기」)의 **화면 구조를 가져오기로** 했다.
화면 문법(제목 위치·일괄 단추·획득 연출)은 이미 반영했으나(백로그 A4), **화면 자체**는 안 가져왔다.

사용자가 스크린샷 20여 장을 주면서 "전부, 그리고 게임화면 구조까지" 가져오자고 했다.
그런데 그대로 다 넣으면 **성장 축이 열 개, 화면이 25개**가 된다. 한 스펙에 다 넣으면 어느 것도 안 끝난다.

**그래서 이 문서는 등급을 나눈다.**

| 등급 | 무엇 | 어디서 정하나 |
|---|---|---|
| **1등급 — 뼈대** | 전투 화면 배치, 메뉴 그리드, 팝업 공통 골격, 이펙트 등급 | **이 문서** |
| **2등급 — 있는 것의 재배치** | 장비·스킬·대장간·성장·펫·던전·도감·출석·오늘과제 | **이 문서** |
| **3등급 — 새 시스템** | 상점·소환·전용무기·동료·영지·아레나·랭킹·계정·보스 패턴 | **각자 별도 스펙** |

**IP 경계**: 화풍과 구조는 가져오되 레퍼런스의 등장인물 이름·고유명(우르스·칠죄종·크로노 등)은
코드·UI·에셋 이름에 넣지 않는다. 던전 이름은 우리 세계관(18.5)의 것을 쓴다.

## 1. 가로 전환

**세로 고정을 폐기하고 가로로 간다** (2026-09-05 사용자 결정).

기획서 1장의 `| 화면 | 세로 고정 |`에는 근거가 적혀 있지 않았다. 레퍼런스가 가로이고,
가져오려는 구조(좌측 세로 탭 + 우측 그리드, 왼쪽 대상 + 오른쪽 목록)가 전부 가로 폭에 기댄다.

**얻는 것**

- **배경을 늘려 메우는 왜곡이 없어진다.** 지금 무대는 `360×480`(3:4)인데 배경은 `far.png` 360×110(하늘) +
  `ground.png` 360×160(땅)이다. 지평선 110 아래를 `stageHeight - horizon = 370`으로 채우느라
  **땅을 2.3배 늘리고 있다**(`battle_stage_game.dart:430`). 가로에서는 무대가 낮아져 늘림이 사라진다
- 진입점 18개 이상을 놓을 자리가 생긴다
- 지금이 가장 싸다 — 화면 11개일 때 바꾸는 것과 25개일 때 바꾸는 것은 비용이 다르다

**얻지 못하는 것 — 오해하지 말 것**

- **백로그 D2가 사라지지 않는다.** D2에는 두 가지가 섞여 있다:
  ① 세로용 `360×480` 규격이 필요하다 → **사라진다**
  ② **지역마다 배경 한 벌씩 10벌이 필요하다 → 그대로 남는다.** 지금은 숲 하나뿐이다
- **지평선 비율을 다시 잡아야 한다.** 무대가 `360×162`(20:9)쯤 되면 하늘 110은 화면의 68%다.
  하늘이 그렇게 넓으면 안 된다. `far`/`ground`가 파일로 분리돼 있어 새로 그릴 필요는 없지만,
  **하늘 높이와 지평선 위치를 다시 정하는 작업이 필요하다** — 가로 전환 계획에 포함한다

**잃는 것**

- **한 손 조작.** 방치형의 이점 하나를 포기한다. 레퍼런스가 가로로 성공했으므로 치명적이진 않다.

**바꿔야 하는 것**

| 대상 | 무엇 |
|---|---|
| `flutter/lib/main.dart` | `portraitUp` 고정 제거 → `landscapeLeft`/`landscapeRight` |
| `GAME_DESIGN.md` 1장 | `세로 고정` → `가로 고정` + 근거 |
| `2026-09-03-art-pipeline-design.md` | 무대 규격을 가로 기준으로 |
| `docs/BACKLOG.md` D2 | **삭제가 아니라 규격 변경** — 세로 360×480 → 가로. 10지역 물량은 그대로 남는다 |
| `ui/game_screen.dart` 외 UI 전반 | 재배치 |

## 2. 전투 화면 — 자리와 성격

**자리는 레퍼런스와 한 칸도 어긋내지 않는다.** 대신 각 자리에 **성격 한 줄**을 못 박는다.
성격이 있으면 "새 화면을 어디 넣지?"를 물어볼 필요가 없다.

| 자리 | 성격 | 우리 것 |
|---|---|---|
| 좌상단 | 나에 관한 것 | `Lv` 뱃지 · 이름 · ⚔전투력 / 골드 · 젬 ＋ |
| 좌측 | 지금 할 일 | 퀘스트 카드 1장 (번호·목표·진행·보상·`>>`) |
| 좌측 아래 | 시간이 차는 것 | 출석부 · 오늘 과제 (각각 남은 시간) |
| 좌하단 | 바깥 소리 | 광고 아이콘. **채팅은 안 한다**(비동기 멀티) |
| 상단 중앙 | 지금 상태 | `▶▶배속` · 층 이름 · 제한 시간 막대 · `x`남은 수 |
| 우상단 | 바깥으로 나가는 곳 | 콘텐츠 · 소환 · 상점 · `≡` |
| 하단 중앙 | 내가 키우는 것 | 장비 · 스킬 · **[대장간 큰 원형]** · 전용무기 · 성장 |
| 우하단 | 같이 싸우는 것 | `AUTO` · 초상(주인공·펫·동료) · 스킬 3칸 + 펫 1칸(숫자=쿨타임) |

**2026-09-05 구현 뒤 실제와 다른 곳**: 좌상단의 `Lv`·이름은 계정 시스템(3등급 7번)이 없어 전투력·골드·젬만 있다.
상단 중앙의 `▶▶배속`은 9절 미결이라 없다. 소환·상점·전용무기·동료·광고는 자리만 있고 잠겨 있다.
하단 중앙의 재화 수량은 아직 안 붙였다(라벨만 있다). 우하단 스킬칸은 3칸 + 펫 1칸이다.

**하단 5칸이 레퍼런스와 정확히 일치한다** — 인벤토리·스킬·대장간·몽둥이·성장.
가운데 하나(대장간)를 **큰 원형으로 강조**하는 것도 그대로 가져온다. 재화 수량이 그 아래 붙는다.

**지금과 달라지는 것 셋**: 층 이동이 독립 팝업 → 콘텐츠 안, 도감이 하단 → 메뉴 그리드,
펫이 하단 → 우하단 초상.

**상단 우측의 "보스 도전" 자리는 비워 둔다.** 레퍼런스는 스테이지 `x-20`이 보스라 별도 도전 버튼이 있는데,
우리는 10마리마다 보스가 자동으로 나온다. 구조가 달라 그대로 못 가져온다 — 9절 미결.

## 3. 메뉴 그리드

레퍼런스는 진입점 20개를 **접지 않고 한 장에 펼친다.** `≡`를 누르면 4열 그리드가 열린다.
이것이 "화면이 늘어나면 어디 넣나" 문제의 답이다 — **칸을 하나 더 붙인다.**

| 행 | 칸 |
|---|---|
| 1 | 콘텐츠 · 소환 · 상점 · `✕` |
| 2 | 캐릭터 · **강화** · 영지 · 동료 |
| 3 | 출석 · 오늘 과제 · 랭킹 · 도감 |
| 4 | 도움말 · 설정 · (빈칸) · (빈칸) |

**안 넣는 것**: 길드 · 우편 · 채팅(비동기 멀티라 없다), 멤버십 · 패스 · 인장(광고 중심 BM).

**대장간과 강화는 다른 화면이다.** 대장간은 재료로 장비를 **만드는** 곳이고(하단 바 큰 원형),
강화는 가진 장비를 **올리는** 곳이다(그리드). 레퍼런스도 이 둘을 나눠 두었다.
강화에 실패를 넣기로 했으므로(8절) 강화는 자기 화면이 필요하다 — 성공확률·재료·실패 보정을 보여야 한다.

**신설이 아니라 이동이다.** 강화는 지금 장비 팝업 안에 카드로 들어 있다(`ui/equipment_panel.dart:210`).
그걸 빼서 자기 화면으로 만든다. 진입점은 둘이다 — 메뉴 그리드, 그리고 장비 팝업 왼쪽 단의 `강화` 버튼.
레퍼런스도 두 곳에서 연다.

## 4. 팝업 공통 골격

여덟 화면에서 한 번도 어긋나지 않는 규칙이다. **새 팝업은 예외 없이 이 골격을 쓴다.**

1. **제목 리본**은 좌상단. `아이콘 + 이름 + ? 도움말`
2. **닫기 `✕`**는 우상단 빨간 원
3. **좌측 초상 줄이 팝업 밖에 남는다.** 팝업 위가 아니라 옆이다.
   초상을 누르면 팝업 내용이 그 대상 것으로 바뀐다 (주인공 · 펫 · 동료)
4. 본문은 **2단**: 왼쪽 = 지금 붙어 있는 것, 오른쪽 = 고를 수 있는 목록
5. **일괄 버튼은 각 단 아래에 따로.** 왼쪽 `자동 장착`, 오른쪽 `일괄 분해` / `일괄 레벨업`
6. **팝업이 떠도 하단 바와 우하단 스킬칸은 계속 보인다.** 화면을 안 덮는다
7. 위험한 동작에는 붉은 경고 한 줄
8. 획득은 전부 같은 연출: 화면 어둡게 → 띠 → 결과 → 아이콘 → "빈 곳을 터치하세요"

**2026-09-05 구현 뒤 실제와 다른 곳**: 4.3의 초상 열은 **대상형 팝업(주인공·펫·동료)에만** 붙는다.
성장·대장간·콘텐츠처럼 대상이 없는 창에는 초상이 없다.
4.6은 **"보인다"까지만** 지켜진다 — 팝업이 하단 바와 우하단 스킬칸 자리를 비우지만,
바깥을 덮은 막이 탭을 먹어 **팝업을 먼저 닫아야 누를 수 있다.** 창을 띄운 채 하단 바를
누르려면 팝업이 라우트가 아니어야 한다(백로그 D5-1).
4.1의 `?` 도움말은 상주 화면 아홉 곳에만 있다. 잠깐 뜨는 창(비교·오프라인 보상·패배 안내)에는 없다.
**스킬 화면만 이 골격 밖에 있다** — `showModalBottomSheet` 로 뜨는 바텀시트라 제목 리본도 닫기 원도 `?` 도 없고,
하단 바와 우하단 스킬칸을 통째로 덮는다. 4절이 세는 화면 중 유일한 구멍이다(백로그 D5-2).
4.6의 "보인다"에는 단서가 하나 더 있다: 막이 55% 검정이라 하단 HUD가 **자리는 남지만 같이 어두워진다.**
본문 2단(4.4)은 골격만 섰고 실제로 쓰는 화면은 장비 하나다 — 나머지 일곱은 아직 1단이다(백로그 D5-2).

## 5. 이펙트와 컷신

**사용자가 1등급으로 올린 요구다.** "스킬 이펙트나 컷신이 화려해야 유저들도 좋아해"

### 5.1 이펙트는 6색 규격에서 뺀다

`ART_GUIDE.md` 1절의 **6색·미니멀 규격은 캐릭터와 몬스터에만 적용된다.**
이펙트에 그 규격을 적용하면 화려해질 수 없다.

이게 타협이 아니라 **의도된 대비**다. 레퍼런스도 캐릭터는 단순한 치비인데 이펙트만 화면을 덮는다.
납작하고 귀여운 몸 위에 밝은 빛이 터져야 타격이 읽힌다. 둘 다 화려하면 아무것도 안 보인다.

| 대상 | 색 규격 | 이유 |
|---|---|---|
| 캐릭터 · 몬스터 · 보스 | **6색** | 100종 일관성, 팔레트 교체 |
| **이펙트 · 컷신** | **제한 없음** | 대비를 만들어야 한다 |
| UI | `pixel_ui.dart` 나무 팔레트 | 무대와 섞이면 안 된다 |

### 5.2 이펙트 층 셋

레퍼런스를 뜯어보면 이펙트가 세 층으로 쌓인다.

| 층 | 무엇 | 예 |
|---|---|---|
| **바닥** | 지면에 깔리는 것 | 주황 균열, 원형 파동, 보스 스킬 예고 장판 |
| **몸** | 대상 위에서 터지는 것 | 빛 폭발, 베기 궤적, 피격 백플래시 |
| **화면** | 화면 전체에 걸리는 것 | 빛기둥, 화면 흔들림, 색 덮개 |

지금 `effects.dart`에는 **몸 층 일부만** 있다. 바닥 층과 화면 층이 없다.
**보스 패턴(3등급)이 바닥 층을 요구하므로** 그때 같이 만든다.

### 5.3 스킬 컷신

스킬을 쓰면 **캐릭터 얼굴 일러스트가 기울어진 사각형으로 화면 왼쪽에서 튀어나온다.**

- 지금 우리 캐릭터는 48~56픽셀 스프라이트뿐이고 **초상화가 없다**
- 최소 4장(4직업) 필요. 표정을 나누면 더
- 컷신은 **스킬 3칸 중 수동 발동에만** 붙인다. 자동 발동마다 뜨면 화면이 못 쓰게 된다

### 5.4 데미지 숫자

한글 단위로 크게 (`104만3810`). 굵은 외곽선. 광역기는 여러 개가 동시에 뜬다.
`number_format.dart`가 이미 한글 단위를 한다(백로그 B3 완료).

## 6. 2등급 — 있는 것의 재배치

시스템은 이미 있고 **껍데기만 바꾼다.** 도메인 코드는 안 건드린다.

| 화면 | 왼쪽 단 | 오른쪽 단 | 일괄 버튼 |
|---|---|---|---|
| **장비** | 착용 6칸을 **원형으로 두르고** 가운데 캐릭터 전신 → `강화` → 전투력 2줄 → 스탯 목록 `▼` | 탭(장비·기타) → **부위 필터 아이콘 줄** → 아이템 그리드 → 소지 재화 + `n/300` | 왼쪽 `자동 장착` / 오른쪽 `정렬` `일괄 분해` |
| **스킬** | **원형 마법진** 위에 슬롯 3개를 흩어 놓고 이름표 | 카드 그리드 4열. `Lv` + **조각 진행바** + `장착중` 배지. 안 연 것은 흑백 | 왼쪽 `자동 장착` / 오른쪽 `일괄 레벨업` |
| **대장간** | 제작 가능 목록 | 선택한 것의 재료·결과 | `자동 제작`(등급·수량 드롭다운) |
| **성장** | 큰 엠블럼 + 훈련 레벨 | 능력치 카드 (`Lv30 MAX` 표시) + 증가율 목록 | `일괄 레벨업` |
| **펫** | 부화 칸 + 탐험 칸 | 보유 펫 그리드 | — |
| **던전** | (콘텐츠 팝업 안) 던전 카드 리스트 | 카드마다 입장권 `n/2`, 잠금 조건 | — |
| **도감** | 지역 선택 | 몬스터 그리드 (미등록은 실루엣) | — |
| **출석 · 오늘 과제** | — | 목록 | `일괄 받기` |

**던전 입장 팝업**은 레퍼런스 것을 그대로 가져온다:
일러스트 + `단계 [－ n ＋]` + **권장 전투력** + 보상 + 입장권 + `[소탕] [입장]`.
`소탕`은 안 싸우고 즉시 보상을 받는다 — 방치형에서 가장 체감이 큰 편의 기능이다.

**콘텐츠 팝업**은 `던전` / `도전` 2탭. 도전 탭은 3등급(아레나)이 들어올 때까지 비어 있다.

## 7. 3등급 — 각자 별도 스펙

**순서는 이렇다.** 앞의 것이 뒤의 것의 자리를 정한다.

| # | 항목 | 왜 이 순서인가 |
|---|---|---|
| 1 | **메뉴 · 설정 · 법규** | 약관·개인정보·계정 삭제가 없으면 **스토어 출시가 막힌다.** 콘텐츠와 무관하다 |
| 2 | **보스 패턴 + 이펙트 층** | 재미의 핵심. 바닥 층 이펙트를 여기서 만들면 뒤가 다 쓴다 |
| 3 | **전용무기 축** | 하단 5칸 중 하나가 비어 있다. 대장간과 경계를 정리해야 한다 |
| 4 | **상점 + 소환** | 수익 축. 확률 공시(법규)가 따라온다 |
| 5 | **동료** | 전투 구조와 좌측 초상 줄을 건드린다 |
| 6 | **영지** | 안에 독립 시스템이 넷(파견·기도·연구·도서관). 아트도 한 벌 더 |
| 7 | **아레나 + 랭킹 + 계정** | 서버 작업이 크다 |

### 보스 패턴이 요구하는 것 (2번 미리 적어 둠)

- **던전마다 배경 한 벌.** 지금 배경은 숲 하나뿐이다
- **던전마다 보스 스프라이트.** 화면 절반 크기 = **180×180 이상**. 단계별 팔레트 변형
- **보스 단계.** `1단계 → 2단계`, 단계마다 HP바가 새로 차고 색이 바뀐다
- **패턴 = 예고 장판 → 대기 → 범위 판정.** `battle_engine.dart`에 **패턴 개념이 아예 없다**
- **전투 시작 카운트다운** `곧 전투가 시작됩니다` + `3 · 2 · 1`

사용자가 브라우저에서 고른 것과 대화에서 정한 것.

| 결정 | 내용 | 파급 |
|---|---|---|
| 화면 방향 | **가로** | 1절 |
| 강화 실패 | **넣는다.** 성공확률 + 실패 보정(연속 실패 시 확률 상승) | 백로그 B의 "실패 없음" 폐기. `equipment.dart`, 던전 산출 재조정 |

| 좌측 초상 | **팝업에서도 유지** | 초상 줄은 **팝업 밖**에 있다(4절 3번). `game_popup.dart`가 아니라 `game_screen.dart`에 고정 열을 두고, 팝업은 그 오른쪽에 뜬다 |

| 채팅 · 길드 · 우편 | **안 한다** | 비동기 멀티 |

## 9. 아직 안 정한 것

- **배속(가속).** 레퍼런스는 광고 2회로 30분 배속을 준다. 기획서 11장이 "13주차에 결정"으로 미뤄 뒀는데,
  **리워드 광고의 가장 자연스러운 소비처**다. 골드 2배·입장권보다 체감이 크다. 4번(상점·소환) 때 같이 정한다
- **영지 도서관**이 무엇인지 아직 못 봤다
- **전용무기의 우리 식 정체.** 레퍼런스는 나무 몽둥이가 20m→50m로 자란다.
  우리 세계관(잠든 용·마력 회수)에 맞추면 "회수한 마력이 뭉쳐 자라는 무기"가 되고,
  뒤로 갈수록 용의 특징이 배어난다 — 몬스터의 용 단계 표와 같은 규칙. 3번 때 정한다
- **캐릭터 초상화 물량.** 컷신에 필요한 얼굴 그림 수(직업 4 × 표정 n)
- **상단 우측 자리를 무엇으로 채울지.** 레퍼런스는 `보스 도전`(스테이지 x-20 재도전)인데
  우리는 10마리마다 보스가 자동으로 나와 구조가 다르다. 비워 두거나 다른 것을 넣는다
- **던전 이름.** 레퍼런스 이름을 쓰지 않는다. `GAME_DESIGN.md` 18.5의 우리 이름을 쓴다
